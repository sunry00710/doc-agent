# Doc Agent 使用手册（三角色版）

> 适用版本：2026-09-11 交付版。文中「管理员 / 上级 / 下级」对应全局角色
> `admin / reviewer / user`（见 README 账号表）。所有按钮显隐由后端权限校验兜底，
> 越权请求会返回 `403 permission_denied`。

## 一、启动与登录

启动步骤见根目录 `README.md`「60 秒启动」。首次演示前确认：

```bash
uv run python scripts/seed_demo.py     # 演示项目 + 文档 + 知识库
uv run python scripts/seed_roles.py    # 三角色账号
uv run python run_dev.py               # 后端 + worker（两个角色都需要在跑）
```

打开 `http://127.0.0.1:5173/`，用下表账号登录：

| 账号 | 密码 | 角色 |
|---|---|---|
| `demo` | `DemoPass-2026!` | 管理员 |
| `shangji` | `ReviewPass-2026!` | 上级 |
| `xiashu` | `StaffPass-2026!` | 下级（员工） |

> 密码仅限本地演示。部署前用管理页或 `scripts/create_user.py` 重建账号并更换密码。

## 二、三角色能做什么（一页速查）

| 能力 | 管理员 | 上级 | 下级 |
|---|---|---|---|
| 编辑草稿 / 保存为新版本 / 提交评审 | ✔ | ✔ | ✔ |
| 评论、向个人知识库收入版本 | ✔ | ✔ | ✔ |
| 评审（开始评审 / 请求修改 / 批准） | ✔（系统级） | ✔（被指派任务） | ✘ |
| 发起晋升治理（批准 / 驳回 / 激活索引 / 撤销） | ✔ | ✔ | ✘ |
| 管理用户与角色、项目成员 | ✔ | ✘ | ✘ |
| 「待我评审」系统队列 | ✔ | 被指派任务可见 | ✘ |

## 三、按角色的操作路径

### 3.1 下级（员工）：`xiashu`

1. **工作台**：左侧选择「演示项目：年度审计报告」。输入「请检查当前文档」查看 Agent 的
   结构化检查结果；输入「起草一份《采购整改情况报告》」触发起草链路（见 §4.5）。
2. **文档**：选择文档 → 选版本 → 在「正文」编辑草稿 → 「保存为新版本」→ 「提交 v1 评审」。
3. **知识库**：把当前版本收入个人库；需要共享时点「申请晋升」，选择目标空间提交。
   晋升审批由上级完成，员工看不到批准按钮（这是权限隔离的正常表现）。
4. **导出 PDF**：文档「正文」页点「导出 PDF」→ 浏览器打印框选「另存为 PDF」。

### 3.2 上级：`shangji`

1. 登录后侧栏有「待我评审」：领取被指派的任务 → 「开始评审」→ 对照原文写批注 /
   「请求修改」或「批准」。
2. **知识库治理**（侧栏或知识库页入口）：批准 / 驳回下属的晋升申请；
   已批准的点「激活索引」正式入库；需要下架时点「撤销」。
3. 上级没有「管理」入口与用户管理权限（与后端一致，直连 API 也返回 403）。

### 3.3 管理员：`demo`

1. **管理 → 项目成员**：查看项目成员、按用户 ID 添加成员并赋项目角色
   （作者 contributor / 项目评审员 reviewer / 项目负责人 owner）。
2. **管理 → 用户与角色**：查看全部用户；通过下拉调整角色；「停用 / 启用」账号。
   系统禁止：停用或降级自己、停用或降级最后一个管理员。
   新账号需要 `uv run python scripts/create_user.py --username 名字 --role user|reviewer|admin`。
3. **管理 → 我的后台任务**：查看索引等后台任务的状态，失败可重试。
4. 管理员也拥有评审与治理能力，用于兜底。

## 四、核心功能速览（各角色通用）

### 4.1 版本对比（含持久化）

文档 → «版本对比» → 选版本 A / B 与对比方式 → 「开始对比」。结果顶部徽章如实标注引擎：

| 徽章 | 含义 |
|---|---|
| 「语义分析 · 模型」 | 由真实模型完成语义对比 |
| 「本地启发式 · 未接入模型」 | 离线演示模式，段落比对 + 相似度，不是模型能力 |
| 「逐行差异 · 已降级」 | provider 不可用时的兜底，附降级原因 |

对比结果会存在会话里：切到「正文」再切回来结果仍在；切换版本或对比方式后旧结果自动清除。
（浏览器会话关闭后清除。）

### 4.2 评审闭环

员工提交 → 上级在「待我评审」领取并开始 → 逐条批注 → 批准或请求修改 →
员工按意见改稿「保存为新版本」→「重新提交」→ 上级继续评审 → 批准 →
文档状态进入「已通过」，可发起晋升进入知识库。

### 4.3 知识库检索与晋升

- 检索范围：个人库（仅自己）+ 项目库（项目成员）+ 共享 / 规范库（全员）。
- 个人库内容可直接收入；共享 / 规范库必须走晋升：申请 → 上级 / 管理员批准 → 激活索引 →
  全员检索可见。撤销后即刻从检索消失。

### 4.4 上传即索引入队（后台任务）

上传新版本成功后，系统会自动创建「knowledge.ingest」后台任务：

- worker 在运行 → 索引很快完成，新内容可被检索；
- worker 没运行 → 上传照常成功，任务显示「排队中」；启动 worker 后自动补做。

### 4.5 Agent 起草

在工作台（或文档页 Agent 面板）输入起草请求，例如「起草一份《采购整改情况报告》，
包含审计范围、主要发现、整改建议」。Agent 返回草稿后：

1. 点回复下方「保存为草稿」→ 草稿正文填入文档编辑器（完整替换当前编辑区）；
2. 人工检查修改后点「保存为新版本」→ 落库为不可变版本。

Agent 不会直接写库；「起草」与「只建议不改稿」的边界一致，落库必须人工确认。

### 4.6 导出 PDF

文档 → «正文» → 「导出 PDF」→ 浏览器打印对话框 → 目标选「另存为 PDF」。
打印版式只保留文档标题与正文（含未保存的草稿会带提示行），界面元素不出现在纸上。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| 上传后搜索不到新内容 | worker 未运行。确认 `run_dev.py` 在跑（它同时拉起 worker），任务面板会显示进度 |
| 对比结果标注「本地启发式」 | 当前是离线演示（MODEL_PROVIDER=fake）。配置真实模型见 `.env.example` |
| 上级点「批准」没有按钮 | 员工角色的正常现象；请用上级或管理员账号操作 |
| 忘记密码 / 需要新账号 | 管理员：管理→用户与角色；或服务器上跑 `scripts/create_user.py` |
| 想重置演示数据 | 备份或删除 `doc_agent.db*` 后依次跑两个 seed 脚本 |

## 四、模型接入（双接口，本轮重点）

`MODEL_PROVIDER` 三选一，`app/providers/factory.py` 装配，**配置缺失时启动即报错**（不静默降级假模型）：

| 值 | 用途 | 需要配置 |
|---|---|---|
| `fake` | 本地离线演示（默认） | 无 |
| `self` | **自用 AI**（OpenAI 兼容，如 DeepSeek） | `SELF_AI_ENDPOINT` / `SELF_AI_API_KEY` / `SELF_AI_MODEL` |
| `internal` | **集团内网 API** | `INTERNAL_API_ENDPOINT` / `INTERNAL_API_KEY` / `INTERNAL_API_MODEL` |

- 自用 AI 例：`SELF_AI_ENDPOINT=https://api.deepseek.com/v1`、`SELF_AI_MODEL=deepseek-chat`
- 集团内网 API 协议**尚未确定**：当前按 OpenAI 兼容假设复用同一 Provider 类。拿到接口文档后，若非兼容协议，新增独立 Provider 类并在 `factory.py` 改接即可，其余调用方无需改动。
- **重要**：部署时必须显式设置 `MODEL_PROVIDER`（否则默认 fake，前端问答仍是"离线演示回复"）。

## 六、检索降级行为的澄清（上轮清单存疑点）

上轮清单称"embedding 下载失败会静默降级为关键词检索"——**取证结论：不准确**。
- 搜索路径 hybrid/dense：embedding 失败 → 抛 500 `index_failure`（**硬失败，非静默**）
- 索引路径：embedding 失败 → 整个索引任务失败（无半成品，`_has_complete_embeddings` 保证）
- 真正的"纯关键词检索"仅发生在 `embedding_provider is None` 的**显式配置**下，属有意设计

因此内网部署**必须**预下载模型（第 5 节第 3 条），否则语义检索会报错而非降级。

## 十、重要发现：语义检索此前从未生效（本轮修复）

**现象**：前端搜索固定请求 `mode: hybrid`（`client.ts:62`），但库里 203 个知识块
**0 个向量行**。`DenseBackend.search` 在无向量数据时直接返回 `[]`，hybrid 静默退化
为纯关键词检索——**全程不报错**，看起来"搜索正常"。

**根因**：`ingest_version()` 支持 `embedding_provider` 参数，但两个调用点
（`router.py` 收入个人库、`promotion_service.py` 晋升激活）都没传，provider 恒为
`None` → 跳过向量生成。这是设计时"离线不强制下载模型"的取舍，但与前端 hybrid
请求形成矛盾：系统承诺语义检索，实际从未提供。

**修复**：
1. `EMBEDDING_ENABLED`（默认 true）控制是否生成向量；两处调用点按配置传 provider
2. `scripts/backfill_embeddings.py` 回填历史数据（本机已回填 136 块，覆盖率 100%）
3. 实测验证：`mode=dense` 查询"供应商报价"命中 3 条（此前必然为空）

**部署注意**：内网离线环境若无法下载模型，两个选择——
- 联网机跑 `prefetch_embeddings.py` 后拷贝缓存（**推荐**，保留语义检索）
- 或设 `EMBEDDING_ENABLED=false`（接受纯关键词检索，此时不要期待语义能力）
